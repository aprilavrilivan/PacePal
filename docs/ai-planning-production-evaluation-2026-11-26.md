## 结论

最终版本得分 **29/30（Excellent）**，可以进入更广泛的集成测试。15 个场景中 14 个完全通过，1 个部分通过；没有出现任何 release-blocking 数据完整性问题：

- 没有丢失已完成任务；
- 没有把缺乏证据的任务错误标成完成；
- 没有破坏依赖关系；
- 没有声称已保存但实际未写入；
- 没有把 14 小时工作静默塞进 10 小时可用时间；
- 需要删除关键前置任务时，计划保持不变并要求明确确认；
- 重复进度消息保持幂等；
- 明确要求重建时，只重建未完成部分并保留完成历史。

唯一的扣分项是 Test 5：夹具把“文献检索”任务标为已完成，而用户又要求把“文献检索”拆细。系统优先保护完成记录，先询问用户指的是已完成的 T3 还是进行中的 T4，没有立即生成子任务。这是安全但偏保守的行为，记 1/2 分。

## 逐场景结果

### Test 1 — Complex Academic Assignment

- **用户输入：** 14 天后提交 2500 字历史论文；主题为 1970 年代湖北农村农田水利与农户住房变化；至少 6 份资料、2 份一手史料、Chicago 脚注；工作日 1.5 小时、周末 3 小时；当前尚未开始。
- **实际响应：** HTTP 200，未要求不必要澄清。AI 明确复述交付物、截止时间和全部硬约束，并计算 27 小时可用时间；生成 5 个阶段、12 个可检查任务，实际计划约 17 小时并保留缓冲。
- **期望：** 覆盖理解要求、资料收集、史料阅读、论证、提纲、写作、Chicago 引注、修订和提交，同时尊重时间与资料约束。
- **计划前/后：** 前：无计划。后：`planVersion=1`，12 个任务；依赖从研究问题与资料地图开始，经过一手/二手史料、笔记、论点、大纲、正文、引注、结构修订，最后校对提交。
- **判定：** Pass，2/2。
- **问题与修复建议：** 无阻断问题。部分史料获取动作受现实馆藏条件影响，产品应继续把模型给出的来源类型视为搜索方向，而不是已找到的真实史料。

- **期望：** 识别信息不足，提出一条聚焦问题，不用长问卷轰炸用户。
- **计划前/后：** 前：无计划。后：仍无计划，也没有计划历史或伪造的交付物。
- **判定：** Pass，2/2。真实网页端复测结果与 API 一致。

- **期望：** T3 保持完成；T4 保持进行中并记录 4/6；T5/T6 不变；不得产生重复任务。
- **计划前/后：** 前：T1–T3 完成，T4 进行中，T5–T8 待开始。后：任务数仍为 8；T4 描述新增“已完成 4/6，剩余 2 份”；T3、T5–T8 状态不变；版本 1 → 2。

### Test 5 — Further Decomposition of a Difficult Subtask

## 成本实测

复杂论文拆解的最终一次请求用量：

- 输入 1,278 tokens，其中 cache read 1,024；
- 输出 3,785 tokens，其中 reasoning 1,328；
- 总计 5,063 tokens；
- Vercel 日志中实际路由为 Baseten：输入约 $0.30/M、输出约 $1.20/M、cache read 约 $0.007/M；
- 估算单次成本：`254×0.30/M + 1024×0.007/M + 3785×1.20/M ≈ $0.00463`。

原来的主模型是 `google/gemini-3.1-flash-lite`。按相同 token 量和 Vercel 标价（输入 $0.25/M、输出 $1.50/M、cache read $0.03/M）估算约 `$0.00577`；不计缓存约 `$0.00600`。因此这次真实路由下 DeepSeek 单次复杂拆解约便宜 **20%**。实际成本主要由输出长度决定；简单澄清和不修改计划的回答通常会更便宜。

DeepSeek 模型页的“from $0.10/M input、$0.29/M output”是最低供应商起价，不是每次一定命中的价格。生产预算应使用 Vercel 日志里的实际路由费率，而不是只使用 `from` 价格。

## 残余风险与建议

1. **单供应商可用性。** 现在严格遵循“一个模型、无 fallback、无 SDK retry”。供应商超时、额度或网关故障会在 60 秒内转为明确的 `model_unavailable`。这让代码和行为可预测，但不能提供多供应商高可用。
2. **Test 5 的安全保守性。** 建议下一版增加“拆解预览但不落库”，让用户在任务状态含糊时仍能快速理解下一步，同时继续保护已完成记录。
3. **真实知识与计划建议的边界。** 模型会建议“地方志、档案、报刊、口述”等来源类型，但不会声称已查到具体史料。若未来加入检索能力，应把检索证据和规划生成分为两个明确步骤。
4. **持续监测。** 应保留 15 场景生产评测作为发布门禁，并记录每次调用的模型、供应商、token、延迟和 `planVersion`，以便发现供应商质量漂移或回归。
